# Справочник CLI и локальной политики

## Синтаксис

```text
python3 guard.py directory [--policy PATH] [--max-bytes N] [--max-files N]
```

| Параметр | Значение | По умолчанию | Семантика |
|---|---|---|---|
| `directory` | Путь к каталогу | Обязателен | Должен существовать и не быть корневым symlink |
| `--policy` | Путь к JSON | Не задан | Загружает организационные маркеры; путь не обязан находиться во входном каталоге |
| `--max-bytes` | Положительное целое | `2000000` | Максимальное число байт одного файла, до декодирования |
| `--max-files` | Положительное целое | `10000` | Максимальное число встреченных файлов, включая неподдерживаемые |
| `-h`, `--help` | Без значения | — | Печатает справку argparse, а не JSON-отчёт |

Пробелы в путях требуют кавычек оболочки. Отдельного `--output`, `--exclude`, `--format`, `--language`, allowlist или режима исправления нет. Превышение `max_files` прекращает весь обход; остальные ошибки файла позволяют продолжить.

## Политика

```json
{
  "markers": ["SyntheticOrg", "Project Falcon"]
}
```

Корень должен быть объектом, `markers` — списком непустых строк. Пустой объект и пустой список допустимы. Пробельная строка отвергается. Пробелы вокруг непустого маркера сохраняются, поэтому `" Team "` ищет строку вместе с пробелами. Регистр игнорируется; специальные символы регулярных выражений экранируются.

Маркеры ищутся как подстроки, без границ слова. Короткий маркер `IT` может совпасть внутри другого слова. Повторяющиеся маркеры и пересекающиеся шаблоны могут дать повторные находки. Неизвестные поля политики сейчас игнорируются, поэтому опечатка `marker` не вызывает ошибку и не включает организационную проверку.

Политика читается через `Path.read_text()` без явного `encoding`: для переносимости alpha-политики используйте ASCII-маркеры либо проверьте локальную кодировку. UTF-8 входных файлов задаётся явно. Строгая схема и явная UTF-8 политика запланированы.

## Коды завершения

| Код | Условие | Действие интеграции |
|---|---|---|
| `0` | Нет находок и зарегистрированных пробелов | Проверить scope, число файлов и намеренные исключения |
| `1` | Есть хотя бы одна находка | Разобрать находки; пробелы покрытия тоже могут присутствовать |
| `2` | Нет находок, но есть пробелы; либо неверный вход/политика | Устранить причину или выполнить другую проверку |

При ошибке исходного каталога или политики stdout содержит `{"error":"Invalid input or policy","status":"not_tested"}`. Ошибки синтаксиса аргументов обрабатывает argparse: справка/диагностика идёт в stderr, код 2, без JSON-отчёта. Ошибка записи stdout, например закрытый pipe, не нормализуется этим контрактом.
