# Справочник CLI и локальной политики

## Синтаксис

```text
python3 guard.py directory [--policy PATH] [--max-bytes N] [--max-files N]
  [--max-total-bytes N] [--max-findings N] [--max-directories N]
```

| Параметр | Значение | По умолчанию | Семантика |
|---|---|---|---|
| `directory` | Путь к каталогу | Обязателен | Должен существовать и не быть корневым symlink |
| `--policy` | Путь к JSON | Не задан | Загружает организационные маркеры; путь не обязан находиться во входном каталоге |
| `--max-bytes` | Положительное целое | `2000000` | Максимальное число байт одного файла, до декодирования |
| `--max-files` | Положительное целое | `10000` | Максимальное число встреченных файлов, включая неподдерживаемые |
| `--max-total-bytes` | Положительное целое | `50000000` | Сумма прочитанных байт, включая неверные файлы и проверку размера |
| `--max-findings` | Положительное целое | `10000` | Максимум сохранённых находок; следующее совпадение останавливает обход |
| `--max-directories` | Положительное целое | `10000` | Бюджет обхода и ветвления, включая корень |
| `-h`, `--help` | Без значения | — | Печатает справку argparse, а не JSON-отчёт |

Пробелы в путях требуют кавычек оболочки. Отдельного `--output`, `--exclude`, `--format`, `--language`, allowlist или режима исправления нет. Превышение `max_files` прекращает весь обход; остальные ошибки файла позволяют продолжить.

## Политика

```json
{
  "markers": ["SyntheticOrg", "Project Falcon"]
}
```

Корень должен быть объектом, `markers` — списком непустых строк. Пустой объект и пустой список допустимы. Пробельная строка отвергается. Пробелы вокруг непустого маркера сохраняются, поэтому `" Team "` ищет строку вместе с пробелами. Регистр игнорируется; специальные символы регулярных выражений экранируются.

Маркеры ищутся как подстроки, без границ слова. Короткий маркер `IT` может совпасть внутри другого слова. Повторяющиеся без учёта регистра маркеры отвергаются. Разные пересекающиеся шаблоны всё ещё могут дать несколько находок. Неизвестные поля, включая опечатку `marker`, и повторные JSON-ключи отвергаются.

Политика — обычный UTF-8 файл без symlink, размером до 65 536 байт. Разрешены максимум 128 маркеров длиной до 256 Unicode-символов каждый; NUL запрещён. Пустые `{}` и `{"markers": []}` отключают PUB-005. Держите политику вне входного дерева, иначе она совпадёт со своими маркерами. Неверная политика даёт код 2 и не отключает запрошенную проверку молча.

## Как выбирать ресурсные лимиты

Для небольшой подготовленной копии текста оставьте значения по умолчанию. Для недоверенного входа снижайте бюджеты; не увеличивайте их только ради чистого результата. `--max-total-bytes` считает прочитанные байты, включая неверную кодировку и дополнительный байт проверки размера; это не сумма размеров успешно проверенных файлов. Для политики отдельно действует предел 65 536 байт.

Файл, который не помещается в остаток общего бюджета, остаётся непроверенным; обход завершается с `total_bytes_limit`. Если последний файл точно исчерпал бюджет, проверка завершается; попытка прочитать следующий поддерживаемый файл останавливает её. Лимит находок срабатывает только на следующем совпадении сверх допустимого числа: ровно допустимое число ещё совместимо с полным покрытием. Частично проверенный по правилам файл включён в `files_inspected`, поскольку полностью прочитан и декодирован; `scan_stopped` и пробел показывают досрочную остановку правил.

Бюджет каталогов включает корень и проверяет число непосредственных дочерних каталогов по остатку до исключений. Эта консервативная проверка может остановить обход, даже если некоторые дети затем были бы исключены. Она не предотвращает предварительное выделение списков элементов внутри `os.walk`. Бюджеты не являются песочницей памяти процесса или времени выполнения.

## Коды завершения

| Код | Условие | Действие интеграции |
|---|---|---|
| `0` | Нет находок, пробелов и исключений; проверен хотя бы один файл | Проверить scope, число файлов и намеренные исключения |
| `1` | Есть хотя бы одна находка | Разобрать находки; пробелы покрытия тоже могут присутствовать |
| `2` | Нет находок, но есть пробелы/исключения; либо неверный вход/политика | Устранить причину или выполнить другую проверку |

При ошибке исходного каталога или политики stdout содержит `{"error":"Invalid input or policy","status":"not_tested"}`. Ошибки синтаксиса аргументов обрабатывает argparse: справка/диагностика идёт в stderr, код 2, без JSON-отчёта. Ошибка записи stdout, например закрытый pipe, не нормализуется этим контрактом.
