# Архитектурные решения

Каждое решение описывает контекст, выбранный подход и последствия. Статус относится к текущему текстовому alpha, а не к будущим инструментам линейки.

## ADR-001 — Python и стандартная библиотека

**Статус:** принято для 0.2.0a1.

**Контекст:** нужен переносимый CLI для чтения текста, регулярных выражений, IP-валидации и JSON. Сложный сервисный runtime для этой задачи не требуется.

**Решение:** использовать `argparse`, `pathlib`, `os`, `re`, `ipaddress`, `json` и `unittest`; не вводить сторонние зависимости в ядро. CI выполняет набор на Python 3.13.

**Альтернативы:** Go упростил бы поставку одного бинарника, но добавил бы отдельный стек; веб-сервис потребовал бы передачи документов, авторизации и хранения. Обе альтернативы не дают необходимой выгоды для текущего объёма.

**Последствия:** запуск требует установленного Python; с 0.2.0a3 доступен wheel; нативного бинарника и installer нет. Отсутствие сторонних зависимостей не доказывает отсутствие ошибок в runtime или коде.

## ADR-002 — локальное чтение без исправлений

**Статус:** принято.

**Контекст:** инструмент работает с материалом, который может содержать секреты; случайная замена значений способна испортить техническую документацию.

**Решение:** файлы открываются для чтения; исходный текст не передаётся во внешние API; исправления выполняются автором в копии.

**Последствия:** нет автоматического обезличивания и отката изменений. Безопасность файловой системы ограничена средствами обычного процесса; изолированная копия остаётся условием работы с недоверенным деревом.

## ADR-003 — JSON и скрытое совпадение

**Статус:** принято.

**Контекст:** отчёт должен подходить для автоматизации и не дублировать найденный секрет.

**Решение:** stdout содержит JSON с относительным путём и номером строки; raw-match не выводится. Политика также JSON, маркеры буквальные.

**Последствия:** необходим локальный доступ к исходной копии для разбора; путь может раскрывать информацию. HTML, SARIF и перевод runtime-сообщений пока не поставляются. Схема JSON и отдельный валидатор доступны в 0.2.0a2.

## ADR-004 — ошибки покрытия отдельно от находок

**Статус:** принято.

**Контекст:** неподдерживаемый файл нельзя оценить как безопасный, а ошибка чтения не должна скрывать результаты остальных файлов.

**Решение:** сохранять `coverage_gaps`; код 1 при находках, иначе 2 при пробелах, иначе 0. Превышение количества файлов прекращает обход.

**Последствия:** потребитель обязан читать JSON и не полагаться только на код. Намеренные исключения записываются отдельно и делают покрытие неполным; пустой вход даёт `empty_scope`.

## ADR-005 — новые форматы через отдельную проверку парсера

**Статус:** предложено; не реализовано.

**Контекст:** PDF/Office/ZIP добавляют риски сложного парсинга, архивных путей, декомпрессионных бомб и пропуска вложений.

**Решение:** прежде чем добавлять формат, определить лимиты, извлекаемые части, неподдерживаемые случаи и набор тестов. Не расширять список расширений без фактической обработки содержимого.

**Последствия:** поддержка бинарных документов откладывается до доказуемой реализации. Это сохраняет честность результатов текстового alpha.

## ADR-006 — отдельная валидация по стандартной схеме

**Статус:** принято для 0.2.0a2.

**Контекст:** типов структуры недостаточно для согласованности покрытия и бюджетов. Реализация полного языка JSON Schema своими силами создаёт лишний риск сопровождения.

**Решение:** сохранить сканер без зависимостей; использовать отдельный `jsonschema==4.26.0` с фиксированными транзитивными версиями для Draft 2020-12. Все ссылки схемы локальны, сетевое разрешение запрещено. Межполевые условия производителя проверять отдельно. Коды валидатора сохраняют смысл сканера; неверный вход или недоступная валидация дают 3.

**Альтернативы:** ручные проверки формы могут разойтись с опубликованной схемой; одна структурная проверка допускает противоречивые счётчики. Сервис валидации потребовал бы ненужной передачи отчёта.

**Последствия:** валидатору нужны установленные зависимости и полный каталог схем. Проверка не подтверждает производителя и не разрешает публикацию. Полные тесты/CI устанавливают отдельное окружение; тесты только сканера доступны командой `python3 -m unittest test_guard -v`.

## ADR-007 — устанавливаемый автономный CLI

Принято для 0.2.0a3. Setuptools с явным списком пакетов и консольными точками входа; прежние команды запуска сохранены. Схема поставляется отдельным пакетом данных, зависимости валидатора остаются дополнительными. Две сборки с фиксированной датой и установка вне рабочей копии дают доказательства поставки, но не публикацию в PyPI и не сборку с полной фиксацией хешей. См. [установку](installation.md).


## ADR-008 — барьеры публикации с явной областью

Принято. Составной Action запускает Python из проверенной версии через буквальные переменные окружения и сохраняет новый внешний отчёт. Hook проверяет явный каталог с отключённым pass_filenames и включённым always_run. Оба передают ненулевой статус. Внешний движок требует отдельного решения адаптера; его отсутствие не подменяется успешной проверкой. См. [интеграции](integrations.md).


## ADR-009 — фиксированный внешний движок и отдельный ответ

Принято для 0.2.0a4. Установленный пользователем Gitleaks 8.24.2 запускается после проверки хеша/версии на отдельной подготовленной UTF-8 копии с явной конфигурацией по умолчанию и скрытыми журналами. Движок не копируется в проект и не обновляется автоматически. Отказы сохраняются, поля с секретами отбрасываются. Отдельный формат сохраняет основной контракт потребителей. Копия не является ОС-песочницей; доказательства реального движка относятся к Linux. См. [адаптер](secret-adapter.md).
