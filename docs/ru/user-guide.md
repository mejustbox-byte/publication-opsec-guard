# Руководство: первая проверка и рабочий процесс

## 1. Подготовка

Нужны Git для загрузки репозитория и Python для выполнения скрипта. Сторонних Python-зависимостей нет. CI использует Python 3.13; совместимость с другими версиями отдельно не заявлена.

```bash
git clone https://github.com/mejustbox-byte/publication-opsec-guard.git
cd publication-opsec-guard
python3 --version
python3 guard.py --help
```

В Windows используйте `python` или `py -3`, если именно так установлен интерпретатор. Последующие примеры используют `python3`; заменяйте только имя команды, сохраняя аргументы.

## 2. Безопасный синтетический пример

Создайте каталог для материала и отдельный файл политики. Политика находится за пределами входного каталога, чтобы её собственные маркеры не стали находками.

```bash
python3 -c "import json; from pathlib import Path; Path('demo-input').mkdir(exist_ok=True); Path('demo-input/notes.md').write_text('Management endpoint: 10.20.30.40\nEnvironment: demo.internal\nProject: SyntheticOrg\n', encoding='utf-8'); Path('demo-policy.json').write_text(json.dumps({'markers':['SyntheticOrg']}), encoding='utf-8')"
python3 guard.py demo-input --policy demo-policy.json > demo-report.json
```

Ожидается код выхода **1** и три находки: PUB-001 на строке 1, PUB-002 на строке 2, PUB-005 на строке 3. `demo-report.json` создан вне `demo-input`, поэтому не анализируется как часть материала.

В POSIX shell код предыдущей команды доступен через `echo $?`; в PowerShell — `$LASTEXITCODE`. Сам сканер пишет JSON, а файл отчёта создаёт перенаправление оболочки.

## 3. Как разобрать результат

Откройте JSON и сначала прочитайте `scope`, `files_inspected` и `coverage_gaps`. Затем по каждой находке перейдите к `asset_id` и строке `evidence.line` в исходной копии. Сканер намеренно не показывает совпадение; контекст изучается в локальном редакторе.

Название правила — это классификация индикатора. Например, приватный IPv4 может быть допустимым учебным примером. Такое срабатывание всё равно существует: текущая версия не умеет исключения и не хранит решения ревьюера.

## 4. Исправление и повторная проверка

```bash
python3 -c "from pathlib import Path; Path('demo-input/notes.md').write_text('Management endpoint: 192.0.2.10\nEnvironment: example.invalid\nProject: Example project\n', encoding='utf-8')"
python3 guard.py demo-input --policy demo-policy.json > demo-report-after.json
```

Теперь ожидается код **0**, пустые `findings` и `coverage_gaps`, `files_inspected: 1`. Это означает отсутствие индикаторов поддерживаемых правил в данном тексте. Это не проверка документов других форматов или секретов всех типов.

## 5. Проверка рабочих материалов

1. Подготовьте отдельную копию только тех файлов, которые планируется передавать.
2. Укажите локальные организационные маркеры в закрытом файле политики.
3. Запишите результат за пределами входного каталога.
4. Разберите каждую находку и каждый пробел покрытия.
5. Исправьте копию, повторите запуск с теми же параметрами.
6. Перед публикацией самостоятельно проверьте неподдерживаемые материалы и чувствительность имён файлов отчёта.

Приватный ключ нельзя делать безопасным только маскированием части текста. Если настоящий ключ уже раскрыт, его замену и отзыв выполняют в системе, которая им управляет. Guard не выполняет эту операцию.

## 6. Что нельзя заключать из успешного запуска

Пустой каталог возвращает 2 и содержит `empty_scope`; исключения также делают покрытие неполным. Код 0 не доказывает отсутствие токенов, очистку EXIF, проверку истории Git или OCR. См. [контракт отчёта](report-format.md).
