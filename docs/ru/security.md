# Безопасность и обработка данных

## Перед запуском

Работайте с изолированной копией материала, не с живым каталогом, который может изменять недоверенный процесс. Запуск от администратора не нужен; используйте учётную запись с доступом только к подготовленной копии. Hardlink могут указывать на чувствительные данные и сейчас отдельно не определяются.

Не увеличивайте лимиты без оценки размера входа. Сканер накапливает все находки, поэтому несколько больших текстов с множеством совпадений могут использовать много памяти. Лимиты ОС/контейнера могут дополнительно ограничить ресурсы, но не входят в текущую поставку.

## Что остаётся локально

Guard не отправляет исходные документы, маркеры или результаты по сети. Загрузка репозитория и GitHub Actions — отдельные операции разработки. Если вы сами загружаете отчёт как CI-артефакт, его получает соответствующий сервис; это решение вашего конвейера.

Значения совпадений не сохраняются в evidence. Пути, номера строк, категории и количество находок остаются. Храните отчёты и политики в закрытом каталоге; не включайте реальный `policy.local.json` в публичный git. `.gitignore` помогает при обычном добавлении, но не предотвращает принудительный commit или раскрытие в issue.

## Разбор ключевого материала

Заголовок приватного ключа — повод проверить исходный контекст. Не отправляйте тело ключа в публичный issue. Если ключ настоящий и уже раскрыт, отзыв и замена выполняются вне Guard. Проверка активности ключей через внешний сервис не реализована.

## Сообщение о проблеме

Воспроизводите проблему на синтетическом входе. Укажите версию инструмента, ОС, команду без чувствительных путей, ожидаемое и фактическое поведение. Не прикладывайте реальные ключи, рабочие экспорты и внутренние названия.

Для сообщения об уязвимости используйте приватный канал репозитория только если он действительно доступен. Наличие включённого private vulnerability reporting не подтверждено; публичный issue с секретом недопустим. Не заявляется SLA ответа или выделенная служба поддержки.

## Ограничения безопасности

Это alpha-инструмент для предварительной проверки текста. Он не является DLP, песочницей, полным сканером секретов или системой автоматического согласования публикаций. Его ограничения перечислены в модели угроз и каталоге правил; технический контроль должен дополняться проверкой материалов владельцем.
