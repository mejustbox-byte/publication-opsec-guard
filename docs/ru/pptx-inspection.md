# Проверка PPTX и переход на documents-0.2

## Назначение и границы

Существующая команда `publication-opsec-documents` принимает `.pptx` и `.docx`. Она локально проверяет ограниченный XML-текстовый профиль OOXML без запуска PowerPoint. Цель — найти оставшиеся внутренние адреса, имена, пути, заголовки ключей, маркеры политики и выбранные метаданные авторов в пакете презентации. Рендеринг слайдов, OCR скриншотов, декодирование медиа, запуск макросов и загрузка ссылок не выполняются.

Установите Guard 0.2.0a6 из проверенной копии. Дополнительная runtime-библиотека парсинга не нужна. Используйте неизменяемую подготовленную копию; `--policy` необязателен и сохраняет контракт маркеров:

```bash
publication-opsec-documents prepared.pptx --policy policy.local.json > presentation-report.json
```

Коды 0/1/2 означают чистую заявленную область, находки и неполную/неверную область. Находки могут сосуществовать с пробелами. Ноль не доказывает безопасность неподдерживаемых визуальных представлений за пределами заявленных проверок.

## Профиль пакета презентации

Основная часть — `ppt/presentation.xml` с transitional PresentationML-корнем `presentation` и немакросным типом содержимого презентации. `[Content_Types].xml` и `_rels/.rels` должны задавать соответствующие основной тип и отношение. `.pptm`, старый `.ppt`, `.ppsx`, Strict OOXML, нестандартные места основной части и макросные типы не принимаются. Это консервативный профиль, а не полная валидация OOXML или графа отношений.

Проверяются все читаемые XML-части: слайды, заметки, образцы/макеты, комментарии и неиспользуемые XML-части. Скрытые слайды не пропускаются. DrawingML-runs `a:t` объединяются внутри абзаца `a:p` перед поиском, поэтому форматирование не обязательно скрывает индикатор. Отдельно проверяются обычный текст и значения атрибутов. Объединение WordprocessingML сохраняется для DOCX.

Источники: [структура PresentationML Microsoft](https://learn.microsoft.com/en-us/office/open-xml/presentation/structure-of-a-presentationml-document), [авторы комментариев](https://learn.microsoft.com/en-us/office/open-xml/presentation/working-with-comments).

## Выбранные метаданные личности

DOC-001 по-прежнему отмечает непустые creator, lastModifiedBy, Company, Manager в docProps. Для прежнего формата частей `ppt/commentAuthors` также отмечаются непустые атрибуты `name` или `initials`. Значения скрываются. Это сигнал для проверки контекста, а не распознавание каждого формата автора/представления личности. Новые/специфические модели авторов не разрешаются семантически; их читаемый текст/атрибуты получают пять обычных проверок.

Находка содержит basename презентации и `part_id`, например `ppt/notesSlides/notesSlide1.xml`. `extracted_line` — строка с единицы во временном текстовом представлении: не номер видимого слайда, порядок показа, положение фигуры и не строка исходного XML. Метаданные не имеют строки. Имена файлов и частей остаются видимыми, хотя совпадения скрыты.

## Медиа, ссылки и лимиты

[Лимиты DOCX](docx-inspection.md) относятся к общему ZIP/XML-парсеру: 8 MB входа, 1 000 частей, 2 MB на распакованную часть, 16 MB XML суммарно, коэффициент сжатия 100, глубина XML 64, 100 000 элементов на часть, 10 000 находок. Только stored/deflated ZIP, без распаковки по путям архива. DTD/entities, неподдержанные кодировки XML, небезопасные/повторные/симлинк-части и шифрование не дают чистого результата.

Изображения, вложенные книги/OLE, аудио, видео и прочие не-XML данные дают `unsupported_part`, внешние отношения — `external_reference`. ZIP-комментарии/дополнительные метаданные и XML-комментарии/инструкции остаются непроверенными пробелами. Диаграмма может иметь читаемый XML и вложенный XLSX: проверка первого не покрывает второй. Команда не проверяет произвольные архивы и не запускает Gitleaks автоматически. Жёсткая квота общей памяти/CPU и доказательства рендеринга PowerPoint отсутствуют.

## Переход: documents-0.1 → documents-0.2

| Поле | 0.1 | 0.2 |
|---|---|---|
| schema_version | documents-0.1 | documents-0.2 |
| scope | docx-utf8-xml-text-and-selected-identity-metadata | ooxml-utf8-xml-text-and-selected-identity-metadata |
| format | Отсутствует | Обязательно: docx, pptx или unsupported |
| Причина неверного пакета | invalid_docx_package | invalid_ooxml_package |
| Остальные поля | Исходный DOCX-ответ | Прежние значения и структуры |

Новая команда выдаёт 0.2 и для DOCX, и для PPTX. Потребители должны учитывать версию и не принимать неизвестную область молча. [Старая схема](../../schemas/documents-0.1.schema.json) сохранена для исторических ответов; [новая](../../schemas/documents-0.2.schema.json) описывает текущие. Основной response-0.2 и secrets-0.1 не меняются. Основной валидатор теперь поддерживает документные ответы; валидация схемы проверяет структуру, а не подлинность источника/семантическое покрытие.

## Проверки и использование перед публикацией

Семь тестовых методов презентаций покрывают чистый профиль/схему, индикаторы в разных runs, заметки/скрытые слайды, скрытие авторов комментариев, неподдержанные медиа/вложения/ссылки, отказ макросам/типам/расширениям, регрессию DOCX и коды CLI. Полный набор содержит 71 метод. Одинаковые тесты выполняются на Linux, Windows и macOS; CI проверяет установку wheel. Минимальные фикстуры не доказывают совместимость с каждым генератором PowerPoint и рендеринг Office.

Запускайте команду отдельным барьером для каждого подготовленного документа. Существующие Action/hook остаются проверкой текстового каталога и не распределяют Office-файлы. Совместно изучайте находки/пробелы, затем отдельно проверяйте визуальный документ и неподдержанное содержимое перед публикацией.
