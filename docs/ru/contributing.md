# Разработка и сопровождение

## Перед изменением

Прочитайте требования, каталог правил и модель угроз. Выберите конкретный дефект или возможность и сформулируйте наблюдаемое поведение. Не меняйте одновременно правила, формат отчёта и CLI без объяснения их связи: это затрудняет оценку совместимости.

## Изменение правила

Добавьте синтетический положительный вход и отрицательный соседний случай. Уточните ID, статическую важность, алгоритм, ограничения и действие пользователя в обеих версиях каталога. Не вставляйте настоящие секреты даже ради регрессии. Изменение regex может расширить ложные срабатывания: тестируйте не только новые совпадения.

## Изменение интерфейса

При изменении поля JSON обновите контракт, пример, потребительский сценарий и версию схемы, если нарушена совместимость. При изменении аргумента обновите CLI-справочник и выполните пример руководства. Не добавляйте поле в документацию раньше, чем оно реализовано.

## Проверки перед PR

```bash
python3 -m pip install -r requirements-validation.txt
python3 -m unittest discover -v
python3 check_docs.py
python3 guard.py --help
git diff --check
```

Дополнительно выполните обе последовательности синтетического примера из руководства и проверьте переход 1 → 0. Откройте README и Mermaid в GitHub Preview. Проверьте локальные ссылки, парность страниц RU/EN и отсутствие рабочих данных.

## Двуязычная документация

`docs/ru` и `docs/en` имеют одинаковый набор имён файлов и совпадающие технические факты. Команды, ID, JSON-поля и версии одинаковы; объяснения переводятся. Перевод должен сохранять исключения и ограничения, а не только основной сценарий. Обновляйте обе страницы одним PR.

## Рецензирование и выпуск

Описание PR объясняет проблему, новое поведение, проверки и оставшиеся ограничения. Перед merge сверяйте CI с текущим head, а не с предыдущим зелёным коммитом. Release notes отражают итоговую поставку; не включают переписку, поручения или историю согласований. Правила лицензирования ещё не определены отдельным LICENSE; наличие публичного репозитория не следует описывать как предоставление MIT/Apache-лицензии.
