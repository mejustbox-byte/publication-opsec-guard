# Валидация всех форматов ответа

## Поддержанные форматы

Существующая `publication-opsec-validate REPORT` теперь распознаёт основной response-0.2, включая ошибку запуска, исторический documents-0.1, documents-0.2, secrets-0.1 и bundle-0.1. Установите дополнительные зависимости валидации. Основному сканеру/распределению они не нужны. Сохраняются строгий UTF-8 JSON, запрет повторных ключей/констант, лимиты байтов/глубины/ошибок и запрет сетевого получения схем. Диагностика содержит коды/безопасные координаты, а не значения входа.

## Структура и согласованность

Каждый формат имеет локальную Draft 2020-12 схему. Документы проверяют согласованность покрытия/пробелов, непустую завершённую область, лимиты частей/XML/находок и совпадение asset находки. Секреты проверяют основной вложенный отчёт, согласованность completed/reason, завершённую область и отсутствие находок незавершённого движка. Общий ответ проверяет каждый вложенный, состояние запроса движка, общее покрытие, непустую область и лимиты файлов/байтов/документов/находок. Основные проверки не меняются.

Корректный отчёт возвращает код проверки 0/1/2; неверная структура/согласованность, отсутствие runtime/схемы — 3. Корректный ответ ошибки запуска возвращает 2. Проверяются утверждения: сфабрикованное, но согласованное происхождение может пройти; подписи, хеши файлов и личность источника не проверяются. Одна схема не реализует межполевые условия. Старый потребитель не должен молча считать неизвестный формат чистым.

## Интеграция и тесты

Запускайте после сканирования, сохраняя первоначальный статус. Для смешанного ответа читайте состояния вложенных отчётов/общие пробелы. Тесты покрывают все форматы, неверные вложенные ответы, противоречия покрытия/лимитов, отсутствующий запрошенный движок и безопасную диагностику. Прежние тесты загрузки/отсутствия сети сохранены. Ошибка runtime не подменяется успехом. Схемы включены в wheel.
