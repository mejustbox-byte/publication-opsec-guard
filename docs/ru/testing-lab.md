# Проверка продукта и воспроизводимость

## Быстрый запуск

Из корня репозитория:

```bash
python3 -m unittest discover -v
```

Ожидается 22 теста и `OK`. Эти тесты используют временные каталоги и синтетические строки. Они не подключаются к рабочей инфраструктуре и не требуют настоящих секретов. Symlink-тест требует среды, в которой разрешено создавать ссылки; конкретный Windows runner такой тест прошёл, но локальные политики Windows могут отличаться.

## Уровни проверки

1. **Правила:** известный индикатор найден; адреса для документации и некорректные адреса не принимаются за RFC1918.
2. **Сбор данных:** неподдерживаемые файлы, symlink, лимиты и ошибки текста сохраняются как пробелы.
3. **CLI:** запуск subprocess проверяет коды выхода и короткий объект ошибки политики.
4. **Платформы:** один и тот же набор выполняется в GitHub Actions на трёх hosted ОС.
5. **Документация:** пример первой проверки выполняется, ожидаемые ID/строки сверяются с реальным JSON; ссылки и пары RU/EN проверяются локально.

## Пробелы качества

Нынешний набор не измеряет precision/recall. Для этого требуется корпус с размеченными положительными и отрицательными случаями, зафиксированная версия правил и подсчёт TP/FP/FN/TN. Текущий зелёный CI не позволяет заявить «100% точности».

Не завершены отдельные проверки недоступного каталога, конкурентной подмены пути, hardlink, суммарной памяти, вывода в закрытый pipe и каждого варианта приватного ключа.

## Добавление сценария

Создайте синтетический вход, укажите правило и ожидаемую находку или пробел. Добавьте отрицательный соседний случай, который предотвращает чрезмерно широкое выражение. Для регрессии сначала опишите наблюдаемый дефект, затем добавьте тест, который воспроизводит его, и только после этого меняйте правило.

Если проверяется поведение ОС, зафиксируйте ОС, Python, архитектуру, режим прав и результат. Вывод CLI, содержащий реальные пути, обезличьте перед публикацией. Для лаборатории не нужны платные облачные ресурсы.
