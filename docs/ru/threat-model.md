# Модель угроз

## Объект защиты

Guard помогает уменьшить раскрытие информации при публикации. Одновременно он обрабатывает недоверенный материал, поэтому сам запуск и его отчёт тоже входят в модель угроз. Защищаемые активы: исходные документы, локальные маркеры, идентифицирующие пути, доступность машины и достоверность результата.

## Участники и допущения

Автор материала может случайно оставить рабочие значения. Недоверенный поставщик файла может подготовить специальный файл, symlink или большой набор совпадений. Получатель отчёта может увидеть путь, хотя значение совпадения скрыто.

Предполагается запуск по изолированной копии в каталоге с доступом только необходимым пользователям. Дерево не должно конкурентно изменяться во время анализа. Компрометация ОС или Python runtime находится вне защиты инструмента.

## Сценарии

| ID | Угроза | Текущий механизм | Остаточный риск |
|---|---|---|---|
| TM-01 | В документе раскрыт адрес/домен | PUB-001/PUB-002 | Неподдерживаемые формы и зоны не обнаруживаются |
| TM-02 | В документе раскрыт пользователь/ключ | PUB-003/PUB-004 | Нет полного детектора секретов, заголовок не доказывает настоящий ключ |
| TM-03 | Раскрыто название проекта | PUB-005 | Требуется корректная локальная политика |
| TM-04 | Вход указывает на файл вне дерева | Symlink пропускаются; доступный `O_NOFOLLOW` | Подмена родителей и hardlink полностью не предотвращены |
| TM-05 | Исчерпание памяти/CPU | Лимит файла и числа файлов | Суммарная память и число находок не ограничены отдельно |
| TM-06 | Утечка через отчёт | Нет raw-match в evidence | `asset_id`, число находок и названия правил остаются |
| TM-07 | Ошибка воспринимается как успех | `coverage_gaps`, код 2 при отсутствии находок | Код 1 может одновременно содержать пробелы; пустой каталог даёт 0 |
| TM-08 | Ложное заявление полного аудита | Поле scope и документация ограничений | Потребитель может проигнорировать ограничения |

## Границы доверия

Политика не является программным кодом, но влияет на число находок и может раскрывать организационные сведения. Отчёт не является доверенным HTML: если внешний потребитель превращает `asset_id` в веб-страницу, он обязан экранировать значение. Guard не поставляет HTML-рендерер.

CI выполняет синтетические тесты исходников. Наличие успешного CI не доказывает безопасность всех пользовательских файлов или изоляцию враждебного дерева.

## Приоритеты снижения риска

Сначала ограничить общий объём данных и находок, затем усилить обработку путей и политику. Новые форматы добавлять только с отдельной моделью угроз парсера: нельзя объявить ZIP или Office поддержанным простым чтением байтов. Качество обнаружения оценивать на опубликованном синтетическом наборе с отрицательными случаями.
