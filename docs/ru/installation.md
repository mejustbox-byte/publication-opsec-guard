# Установка, сборка и поставка

## Что поставляется

Версия 0.2.0a4 содержит конфигурацию сборки wheel/исходного пакета и две команды: `publication-opsec-guard` проверяет текст, `publication-opsec-validate` проверяет сохранённый JSON. У сканера нет сторонних runtime-зависимостей. Для валидатора есть дополнительная группа с теми же точными версиями, что в `requirements-validation.txt`. Wheel включает схему в отдельном пакете данных. Тесты, примеры и прежние точки запуска остаются в репозитории/исходном пакете, а не в runtime-wheel.

## Требования и границы подтверждения

Метаданные требуют Python 3.12 или новее. CI использует Python 3.13 на Linux, Windows и macOS, локальные проверки — 3.12. Независимый от платформы wheel содержит Python-код, а не нативный бинарник сканера. Дополнительные зависимости могут требовать совместимых нативных wheel. Это не доказательство поддержки каждой комбинации ОС/CPU, включая каждый Intel Mac.

## Установка из проверенной копии репозитория

Используйте отдельное виртуальное окружение, чтобы не менять системный Python. Из корня клонированного репозитория:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/publication-opsec-guard /path/to/prepared-text > report.json
```

На Windows создавайте окружение через `python` или `py -3`, вызывайте pip через `.venv\Scripts\python.exe`, а команду через `.venv\Scripts\publication-opsec-guard.exe`. При явных путях активация не нужна. Сохраняйте `report.json` вне проверяемого каталога.

Для валидатора установите дополнительную группу:

```bash
.venv/bin/python -m pip install '.[validation]'
.venv/bin/publication-opsec-validate report.json
.venv/bin/python -m pip check
```

Установка может скачивать средства сборки и дополнительные зависимости; сканирование и проверка отчётов не обращаются к сети. Готовый локальный wheel ядра можно установить с `--no-index --no-deps`. Проект не опубликован в PyPI: установка по одному имени пакета не гарантирует получение этого продукта.

## Сборка и проверка

Средства сборки зафиксированы в `pyproject.toml`: setuptools 84.0.0 и wheel 0.48.0. Установите их в окружение сборки, затем выполните:

```bash
python3 -m pip install setuptools==84.0.0 wheel==0.48.0
python3 -m pip wheel --no-build-isolation --no-deps --wheel-dir dist .
python3 verify_install.py
```

`verify_install.py` дважды собирает wheel с фиксированным `SOURCE_DATE_EPOCH`, сравнивает SHA-256 байтов, устанавливает пакет в чистое окружение вне репозитория, проверяет коды сканера 0/1/2 и код валидатора 3 без дополнительных зависимостей, устанавливает зафиксированное окружение валидации и проверяет сохранённый чистый отчёт. Проверяется схема из wheel, а не случайный импорт рабочей копии. CI сохраняет собранные wheel как артефакты после этой проверки.

Совпадение байтов в одном окружении доказывает повторяемость в этих условиях; независимая воспроизводимость на всех платформах не заявляется. Версии не заменяют фиксацию хешей зависимостей и аудит уязвимостей. Не публикуйте каталоги сборки с локальными данными.

## Совместимость и удаление

Команды `python3 guard.py` и `python3 validate_report.py` сохранены. Теперь им нужен соседний пакет `publication_opsec_guard`: копирования одного файла запуска недостаточно. Версия схемы отчёта остаётся 0.2, `tool_version` становится 0.2.0a3. Удалить установку можно через pip соответствующего окружения или удалением отдельного виртуального окружения. Исходные материалы и отчёты при этом не изменяются.

## Диагностика

Отсутствие команды обычно связано с другим окружением или PATH: используйте полный путь. Результат валидатора `dependency_missing` возвращает 3 до установки дополнительных зависимостей. При `validation_unavailable` проверяйте наличие схемы и целостность окружения. Ошибка скачивания средств сборки не означает, что сканер что-либо проверил. Успешная установка не доказывает безопасность публикации.
