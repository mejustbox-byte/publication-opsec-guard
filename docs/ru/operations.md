# Рабочие сценарии и диагностика

## Документация открытого проекта

Анализируйте отдельный каталог документации. Сам исходный код Guard и каталог правил содержат синтетические индикаторы для тестов и объяснений: при проверке всего репозитория они закономерно дают находки. Это не подтверждение настоящей утечки. Не добавляйте глобальное игнорирование только ради зелёного результата — текущая версия вообще не имеет allowlist.

Отдельно проверяйте бинарные приложения и вложения: поддержка текста не покрывает скриншот с адресом или документ Office с метаданными автора.

## Передача конфигурации подрядчику

Сначала вручную удалите секреты и подготовьте копию. Запустите Guard по этой копии, используя локальную политику названий. Просмотрите результат и исходный контекст. Регулярные выражения не понимают, что конкретная строка содержит API-токен без узнаваемого заголовка ключа. Guard не заменяет специализированный поиск секретов.

## Использование в конвейере

Пример одного шага shell из корня репозитория:

```bash
python3 guard.py prepared-materials --policy policy.local.json > report.json
```

В большинстве CI shell ненулевой код завершит шаг ошибкой. Код 1 требует разбора находок; код 2 — разбора покрытия или входа. Не добавляйте `|| true` только ради продолжения публикации. Если конвейер должен сохранить отчёт при ошибке, настройте отдельный последующий шаг сохранения артефакта и сохраняйте первоначальный код как статус проверки.

Поставляемый `Tests` workflow проверяет тесты продукта; он **не проверяет автоматически материалы любого потребителя**. Готового composite Action и pre-commit hook пока нет. Не запускайте недоверенный код из PR с секретами или привилегиями только ради такого шага.

## Диагностика

| Симптом | Вероятная причина | Проверка и действие |
|---|---|---|
| Код 0, но ничего не проверено | Пустой каталог или только намеренно исключённые подкаталоги | Проверить `files_inspected` и правильность пути |
| Файл `.env` пропущен | Точное имя не имеет `Path.suffix` | Выполнить отдельную ручную проверку; не считать его покрытым |
| Текстовый файл пропущен | Лимит, права, кодировка или NUL | Прочитать `reason`, подготовить корректную копию |
| Маркер не найден | Опечатка поля, другое представление, кодировка политики | Проверить `markers`, буквальный текст и локальный тест |
| Слишком много находок | Короткие маркеры, учебные примеры, повторяющиеся значения | Уточнить область и политику; оценить каждую категорию |
| Найдены пути Windows в JSON не так, как ожидалось | Экранирование меняет исходный текст | Проверка семантики JSON не реализована |
| Отчёт попал во входной каталог | Перенаправление stdout создало файл до обхода | Писать отчёт в отдельный каталог и повторить запуск |

## Правило принятия решения

Сначала оцените достаточность покрытия, затем содержание находок. Сохраните версию инструмента, точную команду и закрытую копию входа в рабочем процессе. Публикуйте только подготовленный материал, прошедший разбор; отчёт Guard сам по себе не является разрешением на передачу информации.
