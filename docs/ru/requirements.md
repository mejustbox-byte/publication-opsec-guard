# Назначение, требования и границы

## 1. Какую проблему решает продукт

Материалы для README, issue, презентаций и передачи подрядчикам нередко содержат фрагменты реальной среды: IP-адреса, внутренние домены, пути домашних каталогов или служебные названия. Эти сведения могут раскрывать устройство инфраструктуры даже при отсутствии пароля. Отдельный класс риска — попадание приватного ключа в текст.

Guard выполняет предварительную проверку копии материалов. Его результат помогает автору найти место для редактирования и объясняет, какие файлы не удалось проверить. Решение о допустимости раскрытия остаётся у владельца информации.

## 2. Пользователи и сценарии

| Пользователь | Вход | Практическая цель |
|---|---|---|
| Автор открытого проекта | Каталог документации и примеров | Найти реальные значения перед commit |
| Системный администратор | Обезличенная копия текстового экспорта | Проверить, не остались ли адреса и имена среды |
| Инженер ИБ | Материалы для отчёта или issue | Получить координаты индикаторов без вывода совпадений |
| Разработчик CI | Подготовленный каталог и локальная политика | Остановить конвейер при находках или неполном покрытии |

Не следует запускать инструмент по всему домашнему каталогу ради проверки одного документа: это расширяет область анализа и создаёт большой отчёт с чувствительными путями.

## 3. Реализованные функциональные требования

| ID | Требование | Фактическое поведение |
|---|---|---|
| FR-01 | Проверка локального каталога | Один обязательный аргумент `directory`; корневой symlink отклоняется |
| FR-02 | Чтение ограниченного файла | До `max_bytes + 1` байт для выявления превышения лимита |
| FR-03 | Пять классов индикаторов | PUB-001–PUB-005; точная логика в каталоге правил |
| FR-04 | Скрытие исходного совпадения | В доказательстве остаются номер строки и `redacted: true` |
| FR-05 | Учёт непроверенных объектов | `coverage_gaps` с причиной пропуска; это не успешная проверка |
| FR-06 | Машинная обработка результата | JSON в stdout и коды выхода 0/1/2 |
| FR-07 | Организационная политика | Необязательный JSON со списком буквальных `markers` |

## 4. Нефункциональные свойства и ограничения

Ядро использует стандартную библиотеку Python и не требует установки сторонних пакетов. Сканирование не делает сетевых запросов и не исправляет файлы. Порядок имён файлов и каталогов сортируется для предсказуемого обхода.

По умолчанию файл ограничен **2 000 000 байт**, число встреченных файлов — **10 000**. Это не предел общей памяти: находки накапливаются в списке, число совпадений отдельно не ограничено. Ограничение суммарного объёма и количества находок относится к будущему усилению.

Имена файлов сохраняются в отчёте относительно корня. Даже при скрытии совпадений они могут быть чувствительными. Формулировка «отчёт обезличен» для текущей версии неверна.

## 5. Поддержка

Поддерживаемые расширения: `.txt`, `.md`, `.rst`, `.json`, `.yaml`, `.yml`, `.toml`, `.ini`, `.conf`, `.csv`, `.py`, `.ps1`, `.sh`, `.xml`, `.html`, `.env`; отдельно распознаётся точное имя `Dockerfile`. YAML, JSON и HTML читаются как текст, их семантика не анализируется. Обычный файл с именем `.env` не имеет расширения по правилам `Path.suffix` и поэтому сейчас пропускается; `settings.env` поддерживается.

Каталоги `.git` и `__pycache__` исключаются намеренно. Их пропуск не записывается как пробел покрытия. История Git не проверяется.

Вне поддержки: PDF, Office, изображения, OCR, архивы, EXIF, IPv6, анализ действительности ключа и полный поиск токенов. Работа тестового набора подтверждена на hosted runners Linux/Windows/macOS; это не подтверждает каждую версию ОС, архитектуру процессора или сценарий с сетевым файловым ресурсом.

## 6. Приёмка alpha и будущей версии

Текущий alpha должен находить синтетические индикаторы пяти правил, не возвращать их значения в доказательстве и сохранять пробелы покрытия. Девять существующих тестов подтверждают часть этого поведения.

До расширенного выпуска нужны отдельные отрицательные случаи для каждого правила, проверки недоступных каталогов, ограничение общей памяти, тесты враждебных деревьев и более строгая политика. Эти требования не объявляются выполненными только потому, что базовый CI зелёный.
