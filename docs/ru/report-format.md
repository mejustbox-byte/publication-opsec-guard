# Контракт JSON-отчёта 0.2

## Назначение контракта

Отчёт предназначен для локального просмотра и интеграции в конвейер подготовки публикаций. В текущей версии это обычный JSON-объект; отдельный JSON Schema валидатор пока не поставляется. Не следует переносить сюда поля будущего общего OPSEC-контракта и считать их реализованными.

## Пример с находкой

```json
{
  "schema_version": "0.2",
  "tool_version": "0.2.0a1",
  "scope": "utf8-text-only",
  "coverage_complete": true,
  "files_inspected": 1,
  "files_encountered": 1,
  "bytes_read": 9,
  "scan_stopped": false,
  "limits": {
    "max_bytes": 2000000,
    "max_files": 10000,
    "max_total_bytes": 50000000,
    "max_findings": 10000,
    "max_directories": 10000
  },
  "exclusions": [],
  "findings": [
    {
      "check_id": "PUB-001",
      "asset_id": "notes.md",
      "status": "fail",
      "severity": "high",
      "evidence": {
        "line": 1,
        "redacted": true
      },
      "remediation": "Replace internal addresses with documentation addresses."
    }
  ],
  "coverage_gaps": []
}
```

`coverage_complete: true` и наличие находок совместимы: первое относится к зарегистрированным пробелам обработки, второе — к содержимому. Это не оценка безопасности.

## Верхний уровень

| Поле | Тип | Значение |
|---|---|---|
| `schema_version` | string | Версия формы результата; сейчас `0.2` |
| `tool_version` | string | Версия реализации; сейчас `0.2.0a1` |
| `scope` | string | `utf8-text-only`, ограничивает трактовку результата |
| `coverage_complete` | boolean | True, когда пробелы и исключения пусты |
| `files_inspected` | integer | Число успешно прочитанных и декодированных поддерживаемых файлов |
| `files_encountered` | integer | Встреченные до остановки файлы, включая неподдерживаемые |
| `bytes_read` | integer | Фактически прочитанные байты входа, без байт политики |
| `scan_stopped` | boolean | Лимит остановил обход; обычные пропуски оставляют false |
| `limits` | object | Пять действующих лимитов с именами CLI и подчёркиваниями |
| `exclusions` | array | Намеренно пропущенные каталоги |
| `findings` | array | Отдельные совпадения правил; не список всех выполненных проверок |
| `coverage_gaps` | array | Пропуски, ошибки обработки и превышение лимита количества |

Намеренные исключения `.git` и `__pycache__` записываются в `exclusions` с `asset_id` и `reason: excluded_directory`; покрытие становится неполным. Если не проверен ни один файл, добавляется `empty_scope`, даже при наличии других пробелов. Отчёт не содержит времени запуска, имени хоста, SHA входных файлов или политики; поэтому сам по себе не доказывает, какие байты были проверены.

## Запись находки

`check_id` — ID правила; `asset_id` — относительный путь, не глобальная стабильная идентичность объекта. `status` всегда `fail`. `severity` берётся из правила. `evidence.line` — целое, строки нумеруются по символам `\n`, начиная с 1. `redacted` всегда `true`; колонка и текст совпадения не сохраняются. `remediation` — английская статическая рекомендация независимо от языка документации.

В этой реализации нет отдельных записей `pass` или `not_applicable`, агрегации по объектам и идентификатора находки. Потребитель не должен выводить «правило пройдено» только из отсутствия записи, не проверив объём покрытия.

## Пробелы покрытия

```json
{
  "asset_id": "diagram.png",
  "status": "not_tested",
  "reason": "unsupported_format"
}
```

| `reason` | Значение | Что делать |
|---|---|---|
| `unsupported_format` | Имя/расширение не входит в список | Проверить другим способом; не переименовывать бинарный файл ради обхода |
| `symlink` | Символьная ссылка пропущена | Подготовить обычную изолированную копию нужного файла |
| `size_limit` | Файл превышает `max_bytes` | Оценить ресурсный риск, разделить материал или обоснованно увеличить лимит |
| `binary_content` | Есть нулевой байт | Проверить формат другим инструментом |
| `not_regular_file` | Объект не является обычным файлом | Удалить специальные объекты из подготовленной копии |
| `unreadable_or_invalid_utf8` | Ошибка чтения или UTF-8 | Проверить права и кодировку; исходный файл не менять автоматически |
| `directory_unreadable` | Ошибка обхода каталога | Уточнить доступ; запись не содержит пути |
| `file_count_limit` | Встречен файл за лимитом | Сузить область или обоснованно изменить лимит; обход остановлен |
| `total_bytes_limit` | Исчерпан общий бюджет чтения | Сузить копию; проверить остаток отдельно |
| `finding_count_limit` | Следующая находка превысила бы лимит | Устранить текущие находки и повторить; результат частичный |
| `directory_count_limit` | Превышен бюджет каталогов/ветвления | Сузить дерево каталогов |
| `empty_scope` | Ни один поддерживаемый файл не проверен | Исправить область или проверить форматы иначе |

У `directory_unreadable`, `file_count_limit`, `directory_count_limit` и `empty_scope` отсутствует `asset_id`. Код интеграции должен принимать это, а не падать на обращении к обязательному ключу.

## Ошибка запуска

```json
{"error": "Invalid input or policy", "status": "not_tested"}
```

Это другой объект, без обычных полей отчёта. Сначала проверяйте наличие `error`; затем `schema_version` и `scope`. Не записывайте такой объект как успешный аудит. Отдельно обрабатывайте ошибку argparse, при которой JSON вообще не выводится.

## Приватность и хранение

Скрытие совпадений уменьшает раскрытие значений, но пути остаются открытыми. При передаче результата наружу замените чувствительные имена файлов или передайте только агрегированное число находок. Срок хранения, права доступа и удаление отчёта задаются рабочим процессом организации; сканер не управляет ими.

## Переход с 0.1

Для новых полей требуйте `schema_version: 0.2`. Не заменяйте отсутствующие счётчики и исключения отчёта 0.1 выдуманными значениями. Пустой вход раньше давал 0, теперь 2. Исключённые каталоги раньше не меняли покрытие, теперь делают его неполным. Находки по-прежнему имеют приоритет кода 1. Эти изменения предотвращают принятие пустого или частично исключённого дерева за чистую проверку. Файл схемы и самостоятельный валидатор остаются в плане.
