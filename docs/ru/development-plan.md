# План разработки и критерии готовности

## Текущее состояние

Текстовая alpha 0.2.0a6 содержит пять правил, контракт 0.2 и 71 тестовых методов. M1–M5 реализованы. M2 включает поставляемую схему, отдельный валидатор, размеченные фикстуры ответов и автоматические проверки двуязычной документации; подцикл DOCX M6 реализован; остальные бинарные форматы в плане.

## Этапы

| Этап | Содержание | Проверяемый результат | Условие завершения |
|---|---|---|---|

| M2: реализован | Версионированная схема, явные исключения и пустой вход | Схема и валидатор, обновлённые RU/EN примеры | Потребитель отличает ошибку запуска, пустую область и результат |
| M3: реализован | Положительные/отрицательные/граничные случаи для каждого ID | Размеченный синтетический корпус | Все заявленные формы имеют тест; опубликованы измерения без преувеличений |
| M4: реализован | Упаковка CLI, фиксируемые зависимости, повторяемая сборка | Установочный артефакт и инструкция | Установка проверена в чистой среде; версия отражена в отчёте |

## Порядок одного полного цикла

Требования и границы → ADR и модель угроз → реализация → тесты → проверка документации и публичных артефактов → PR → CI на точном head → слияние → выпуск с ограничениями. Если этап не завершён, статус не подменяется успешным предыдущим этапом.

## Definition of Done для изменения

- Поведение описано на обоих языках и совпадает с кодом.
- Есть позитивный и негативный тест, а для обработки данных — ошибочный вход.
- Нет реальных секретов и рабочих экспортов в примерах.
- Изменение контракта сопровождается версией и инструкцией миграции.
- CI проверен для конкретного SHA; примеры выполнены, ссылки разрешаются.
- Release notes описывают фактическую поставку и остаточные ограничения.

## Зависимости и риски

Специализированный поиск секретов потребует выбора внешнего движка, лицензии, версии и политики проверки активности: до этого интеграция не объявляется существующей. Бинарные форматы требуют ограничений распаковки и парсеров. macOS hosted CI не доказывает совместимость с каждым Intel Mac; такая поддержка требует отдельного результата на соответствующей архитектуре.

## Очередь линейки

После завершения этого проекта следующий самостоятельный цикл — общий контракт OPSEC-отчётов, затем лаборатория, аудит восстановления, сетевой аудит и Detection Readiness. Существующие аудиторы интегрируются после проверки их текущих форматов. Этот план не означает фоновое выполнение или автоматически созданные ресурсы.
