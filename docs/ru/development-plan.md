# План разработки

1. Сверить существующий код, ветки, CI и активную работу; сохранить исходный SHA.
2. Утвердить границы MVP через требования, ADR и матрицу.
3. Реализовать ядро и интерфейс; ошибки не скрывать.
4. Проверить каждый ID матрицы и интеграционные сценарии.
5. Выполнить аудит секретов, зависимостей и публичных артефактов.
6. Подготовить двуязычные руководства и release notes.
7. Создать PR, проверить CI на точном SHA, слить только при выполненных критериях.
8. Выпустить версию с явными ограничениями; затем начать следующий проект.

Большой цикл заканчивается одним проверяемым результатом или конкретным внешним блокером; незавершённый пункт не маркируется выполненным.
