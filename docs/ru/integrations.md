# Интеграция с GitHub Action и pre-commit

## Назначение и состав

`action.yml` — составной Action для проверки явно заданного каталога подготовленных материалов с сохранением JSON. `.pre-commit-hooks.yaml` — Python-hook с установкой в окружение pre-commit. Оба сохраняют решение сканера: 0 — нет находок и записанных пробелов, 1 — находки, возможно с пробелами, 2 — неполное покрытие или неверный вход. Они не разрешают публикацию и не находят все виды токенов.

## GitHub Action: настройка

Python 3.12+ должен быть доступен как `python3`; перед Action используйте setup-python. Пути отсчитываются от рабочей копии вызывающего проекта. `directory` и `report` обязательны, `policy` необязателен. Отчёт должен находиться вне проверяемого каталога, файл ещё не должен существовать. Это предотвращает самопроверку отчёта и случайную перезапись. Для повторных запусков и matrix используйте разные пути.

Замените `REVIEWED_COMMIT_SHA` проверенным неизменяемым коммитом этого репозитория, содержащим Action; сам заполнитель использовать нельзя. Если политика не нужна, удалите `policy`. До этого шага создайте каталог подготовленных материалов:

```yaml
permissions:
  contents: read
jobs:
  publication:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-python@v6
        with:
          python-version: '3.13'
      - uses: mejustbox-byte/publication-opsec-guard@REVIEWED_COMMIT_SHA
        with:
          directory: prepared-materials
          policy: policy.local.json
          report: ${{ runner.temp }}/publication-opsec-report.json
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: publication-opsec-report
          path: ${{ runner.temp }}/publication-opsec-report.json
```

Ненулевой результат завершает шаг проверки ошибкой. Выход `exit-code` записывается до завершения runner. `if: always()` сохраняет отчёт после находок и ошибок покрытия, но не превращает проверку в успех. Ошибка настройки/места отчёта возвращает 2 и может не оставить файл. Публикация должна зависеть от успешной проверки и отдельной оценки человеком. Не используйте `continue-on-error` или `|| true` для публикации после ошибки.

Action выводит только код завершения. JSON сохраняет имена файлов и номера строк: публичная загрузка такого артефакта не считается безопасной автоматически. Настройте доступ и срок хранения по чувствительности путей и метаданных. Входы читаются из переменных окружения, а не подставляются в shell-команды. Action не устанавливает сканер, не отправляет секреты и не проверяет действительность учётных данных онлайн.

## pre-commit: явная область

Создайте `.pre-commit-config.yaml` в своём репозитории, заменив заполнитель ревизии проверенным коммитом:

```yaml
repos:
  - repo: https://github.com/mejustbox-byte/publication-opsec-guard
    rev: REVIEWED_COMMIT_SHA
    hooks:
      - id: publication-opsec-guard
        args: [prepared-materials, --policy, policy.local.json]
```

Отдельно установите pre-commit, затем выполните `pre-commit install` и `pre-commit run publication-opsec-guard --all-files`. Пакет сканера автоматически устанавливается в окружение hook; нужен Python 3.12+. Hook выводит JSON сканера в журнал pre-commit, включая имена файлов. Храните организационную политику приватно.

`pass_filenames: false` означает проверку каталога из `args`, а не списка staged-файлов. `always_run: true` предотвращает пропуск только из-за фильтра файлов. Аргумент каталога обязателен. Проверка всего репозитория обычно захватывает синтетические примеры и исключения, поэтому может завершиться ошибкой. Выбирайте отдельный каталог подготовленных материалов: hook выполняет предварительную проверку публикации, а не гарантирует проверку всех staged-файлов. Локальную проверку можно обойти; используйте CI как дополнительный барьер.

## Проверяемое поведение

Четыре subprocess-теста покрывают чистый материал, находки, неподдерживаемый формат, неверную политику, запрет отчёта внутри области, защиту от перезаписи и буквальные имена каталогов, похожие на shell-код. `verify_hook.py` использует реальный manifest hook во временном Git-репозитории и проверяет чистый результат/находки через pre-commit 4.3.0. CI запускает локальный составной Action на чистом синтетическом материале и материале с находками после полного набора тестов. Одинаковые проверки выполняются на Linux, Windows и macOS. Это синтетическая проверка интеграций, а не доказательство всех пользовательских workflow.

## Граница специализированного движка

Дополнительный [фиксированный адаптер Gitleaks](secret-adapter.md) поставляется отдельной командой в 0.2.0a4. Основные Action/hook запускают только текстовый сканер. При необходимости добавьте отдельный шаг адаптера; недоступный движок не означает чистый результат. Реальный движок проверен только на Linux. Проверка заголовков ключей сама по себе остаётся неполным поиском секретов.

## Диагностика

Код 2 без отчёта: проверьте место сохранения, существующий файл, права и попадание внутрь области. Код 2 с отчётом: изучите coverage gaps или ответ ошибки запуска. Hook пропущен: сверяйте ID и конфигурацию; в поставляемом manifest включён always_run. Нет `python3`: настройте интерпретатор до Action. Успешный барьер относится только к проверенной UTF-8 области и текущим пяти правилам.

Источники разработчиков: [настройки pre-commit](https://pre-commit.com/), [Gitleaks](https://github.com/gitleaks/gitleaks).
