# Development plan

1. Inspect existing code, branches, CI and active work; retain baseline SHA.
2. Establish MVP boundaries through requirements, ADR and matrix.
3. Implement core and interface; preserve errors.
4. Verify each matrix ID and integration scenarios.
5. Audit secrets, dependencies and public artifacts.
6. Prepare bilingual guides and release notes.
7. Open PR, verify CI at exact SHA, merge only when acceptance criteria are met.
8. Release with explicit limitations; then start the next project.

A large cycle ends with a verifiable outcome or a specific external blocker; unfinished items remain unfinished.
