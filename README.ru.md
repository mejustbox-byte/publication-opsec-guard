# Publication OPSEC Guard

### Проверка текста перед публикацией

**Локально · Только чтение · Пять правил · JSON без исходных совпадений**

Guard помогает заметить рабочие адреса, внутренние домены, пользовательские пути, заголовки приватных ключей и организационные маркеры в подготовленных материалах. Он показывает файл и строку, сохраняет непроверенные объекты и оставляет решение о публикации владельцу информации.

> **0.2.0a6 — текстовый alpha-прототип.** Основной сканер проверяет текст; отдельная команда поддерживает ограниченный XML-профиль DOCX. PDF, изображения, произвольные архивы и история Git не проверяются. Код 0 не является гарантией отсутствия секретов.

## Какую задачу решает

Перед публикацией README, issue или обезличенной конфигурации нужно проверить, не сохранились ли сведения реальной среды. Guard выполняет повторяемую предварительную проверку локальной копии. Результат позволяет перейти к конкретной строке без дублирования чувствительного совпадения в JSON.

## Возможности

| Правило | Что ищет | Для чего |
|---|---|---|
| PUB-001 | IPv4 в RFC1918 | Раскрытие внутренней адресации |
| PUB-002 | `.local` / `.internal` | Раскрытие внутренних имён |
| PUB-003 | `/home/`, `/Users/`, Windows home paths | Идентифицирующие имена пользователей |
| PUB-004 | Заголовки приватных ключей | Возможный приватный ключевой материал |
| PUB-005 | Буквальные маркеры политики | Служебные названия и идентификаторы |

## Быстрый старт

```bash
git clone https://github.com/mejustbox-byte/publication-opsec-guard.git
cd publication-opsec-guard
python3 guard.py /path/to/prepared-text > report.json
```

Python должен быть установлен; сторонние пакеты не нужны. Отчёт записывайте **вне проверяемого каталога**. В Windows при необходимости замените `python3` на `python` или `py -3`. Полный воспроизводимый пример с ожидаемым результатом — в [руководстве](docs/ru/user-guide.md).

| Код | Значение |
|---|---|
| 0 | Нет находок и зарегистрированных пробелов; проверить число файлов и scope |
| 1 | Есть находки; пробелы покрытия тоже могут присутствовать |
| 2 | Неполное покрытие без находок либо ошибка входа/политики |

## Что важно знать

Файлы читаются как UTF-8 по ограниченному списку расширений; JSON/YAML не анализируются семантически. Точное имя `.env` теперь проверяется. `.git` и `__pycache__` записываются как исключения, покрытие неполное. Raw-match скрыт, но имена файлов остаются. Суммарная память отдельно не ограничена; используйте изолированную копию для недоверенного дерева.

## Проверка сохранённого отчёта

Отдельный [валидатор отчёта](docs/ru/report-validation.md) проверяет поставляемую схему и согласованность покрытия/бюджетов. Установите зависимости командой `python3 -m pip install -r requirements-validation.txt`, затем выполните `python3 validate_report.py report.json`. Коды 0/1/2 сохраняют смысл сканера; неверный вход или недоступная валидация дают 3. Проверка не подтверждает источник и не одобряет публикацию.
